    46 | /// M9: `--max-columns N` (JSON only, per call): the `text` of a row whose line
    47 | /// is longer than N bytes is emitted as a WINDOW of at most N bytes around the
    48 | /// match, with where the window starts and how long the whole line is. Fixed
    49 | /// once per run before scanning; the workers only read it (0 = off, the byte
    50 | /// for byte pre-M9 behaviour).
    51 | ///
    52 | /// Why: on a real tree with `node_modules` (minified and generated lines),
    53 | /// cutting long lines to a window around the match saves ~58 % of the compact
    54 | /// output's REAL tokens (58.4 % at N=400 with the real implementation; the
    55 | /// pre-implementation simulation said 64.9 %) with the match intact in every row — measured against a
    56 | /// real BPE, register in `evidence/agent-native/m9/`. The rule fixed before the
    57 | /// run (>= 20 % saving, match never cut) says IMPLEMENT.
    58 | ///
    59 | /// The contract (GUIA §4s), all of it verified by `m9_conformance.py`:
    60 | ///   * only rows whose emitted text IS the line are windowed; a row without a
    61 | ///     span (context, `-v`, `--passthru`) and a `--replace` row (the
    62 | ///     substituted line, where the match no longer marks a position) are
    63 | ///     emitted WHOLE;
    64 | ///   * the match is never cut: the window always contains it, and if the match
    65 | ///     alone does not fit in N bytes the window IS the match;
    66 | ///   * a UTF-8 character is never split (the window is aligned to codepoint
    67 | ///     boundaries), so every windowed `text` decodes;
    68 | ///   * `col`, `byte_start` and `len` keep their whole-line meaning, so nothing
    69 | ///     is lost: `line_start = byte_start - (col - 1)`, the whole line is
    70 | ///     `file[line_start .. line_start + line_len]` and the window starts at
    71 | ///     `line_start + win_start` (with `--provenance`, verifiable by hash).
    72 | ///
    73 | /// Where the extra information travels (additive, and ONLY when a row is
    74 | /// windowed): `zgrep/1` gains `win_start` + `line_len` next to `text`;
    75 | /// `zgrep/1c` gains the `w` suffix on the row tag and two positional elements,
    76 | /// `[t+"w",line,col,byte_start,len,ventana,win_start,line_len]` (+ `match` when
    77 | /// it is not derivable inside the window). An unwindowed row is byte-identical
    78 | /// to pre-M9 output, so a reader that does not know the flag sees nothing new.
